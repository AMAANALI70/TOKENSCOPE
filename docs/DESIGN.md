# TokenScope: Design and Approach

## 1. Problem

Agent loops re-send their whole context on every LLM call. Cost therefore grows with
(context size x number of calls), and most of the context is not new: it is tool schemas,
earlier tool outputs and history. Teams can see a total bill but not *which part of the
context* caused it, so they optimize blindly (usually by shortening the system prompt,
which is rarely the problem).

## 2. Thesis

> Measure first, then optimize, then prove nothing broke.

Existing tools mostly sit in the middle step (compress this text) and report savings
without an end-to-end quality check. TokenScope owns the first and last steps and keeps
the middle step simple, deterministic and verifiable.

| Stage    | Question it answers                              | Status |
|----------|--------------------------------------------------|--------|
| Profile  | Where do the tokens go, per category and tool?   | v0.1   |
| Detect   | Which patterns are wasteful? (dupes, unused tools, cache-hostile layout) | v0.2 |
| Optimize | Apply trimming, dedup, cache-aware ordering      | v0.3   |
| Verify   | Did cost drop *without* changing task outcome?   | v0.4   |

## 3. Non-goals (for now)

- No learned or LLM-based compressor (research-heavy, expensive to evaluate).
- No hosted service or web dashboard.
- No live proxy until offline analysis is solid.
- No exact billing reproduction (provider cache discounts, batch pricing).

## 4. Architecture

```
 trace file (JSONL)
        |
   loader.py --(detect_format)--> parsers/{openai_chat, anthropic_messages}
        |                                   |
        v                                   v
   neutral model (models.py): Trace -> Call -> Segment(category, text, tool_name)
        |
        v
   attribution.py  <--  tokenizers.py (TokenCounter: tiktoken | heuristic)
        |
        v
   TraceAttribution --> report.py (rich table | JSON)  --> cli.py
        |
        +--> (v0.2) detectors/  --> findings
        +--> (v0.3) optimizers/ --> rewritten Trace
        +--> (v0.4) verify/     --> cost vs success report
```

Principle: **everything downstream of the parsers sees only the neutral model.**
Adding a provider = one parser module. Adding a detector or optimizer never touches
parsing.

## 5. Data model

- `Category`: `system`, `tool_schema`, `user`, `assistant`, `tool_call`, `tool_result`,
  `output`. `output` is tokens generated by the model in that call; the rest are input.
- `Segment(category, text, tool_name?, message_index?)`: the unit of attribution.
- `Call`: input segments, optional output segments, optional provider `Usage`.
- `Trace`: ordered calls of one agent run.
- `Usage.input_tokens` is always the *total* prompt size (Anthropic reports cached and
  uncached separately; the parser sums them).

## 6. Trace format

One JSON object per line = one LLM call. A top-level JSON array is also accepted.

OpenAI-style:
```json
{"model":"gpt-4o","tools":[...],"messages":[...],
 "response":{"choices":[{"message":{...}}],"usage":{"prompt_tokens":0,"completion_tokens":0}}}
```
Anthropic-style:
```json
{"model":"...","system":"...","tools":[...],"messages":[...],
 "response":{"content":[...],"usage":{"input_tokens":0,"cache_read_input_tokens":0,
 "cache_creation_input_tokens":0,"output_tokens":0}}}
```
`response` is optional. Without it, input attribution still works; output and drift do not.

Format detection looks for `system`, `input_schema` on tools, or `tool_use`/`tool_result`
blocks. Pass `--format` explicitly when in doubt.

## 7. Attribution method

For each call, for each input segment:
1. Fingerprint = sha256(category + text)[:16].
2. Token count = counter(text), cached by fingerprint (history repeats a lot).
3. Add to `billed[category]`. If the fingerprint was never seen earlier in the trace,
   also add to `unique[category]`.
4. If the segment has a tool name, add to `by_tool[(category, tool)]`.

### Metrics

| Metric | Definition | Why it matters |
|---|---|---|
| billed | sum of input tokens over all calls | what you pay for (before cache discounts) |
| unique | tokens counted at first appearance only | the "information" in the run |
| resend multiplier | billed / unique | how often the same content is re-paid; high means fix context management |
| calibration factor | reported input / estimated input, over calls with usage | trust level of absolute numbers; ~1.0 is good |

Category *shares* are usually trustworthy even when the tokenizer is approximate,
because error is roughly proportional across categories. Absolute numbers are only as
good as the calibration factor says.

## 8. Tokenization strategy

- `tiktoken` (`o200k_base`): exact for recent OpenAI models, approximate for others.
- Heuristic `ceil(chars/4)`: zero dependencies, works offline, deterministic.
- `auto`: tiktoken if available, else heuristic. The chosen tokenizer is always printed.
- Message framing overhead (a few tokens per message) is not modelled; it shows up as
  drift against provider-reported usage.

## 9. Evaluation methodology (v0.4, designed now so v0.1 data fits it)

Goal: for every optimizer, report **cost saved vs task success** on the same tasks.

1. Record N tasks (start with 20-30) with a fixed agent, model and temperature 0 where possible.
2. Replay each task with optimizer off (baseline) and on.
3. Measure tokens and cost from provider usage, not estimates.
4. Measure success with a task-specific check (tests pass, expected answer matches).
5. Repeat runs to estimate variance. Report mean and spread, not a single number.
6. Publish the cost-vs-success Pareto chart, including optimizations that hurt.

Compare against at least one existing tool (e.g. LLMLingua-2) as a baseline.

## 10. Testing strategy

- Parsers: golden inputs per provider, plus malformed inputs (error messages with line numbers).
- Attribution: tiny hand-computed traces where the right answer is obvious (see tests).
- Property to maintain: sum of category tokens == estimated input for every call.
- CLI: JSON output is parsed and asserted, so it can be relied on by scripts.
- CI: ruff, mypy --strict, pytest on Python 3.10 to 3.12.
